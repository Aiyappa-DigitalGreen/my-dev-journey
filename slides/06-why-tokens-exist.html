Backend · Auth · Topic 06

Why tokens exist.

The forgetful server, the club wristband, and why your password should travel only once.

Three words first

Client · Server · Request

  • Client: the thing that asks (the Swiggy app on your phone).
  • Server: a computer elsewhere that answers (Swiggy's data centre).
  • Request: one message from client to server ("show my past orders").
1 · The problem

The server forgets you after every request

  • Request 1: "I'm Aiyappa + password" → ✅ welcome
  • Request 2, one second later: "show my orders" → 🤷 who are you?
  • Official word: stateless, meaning no memory between requests.
  • Naive fix: send the password every tap → about 1,000 exposures a week.
2 · The picture

The club wristband 🎟️

Pay and show ID once at the door. Get a wristband. Any bouncer lets you back in. You never hand over your wallet again.

Hand over something cheap to lose instead of the valuable secret.

Password vs token

Why the wristband is safer

  • Where: password often reused everywhere → token works for one service only.
  • How long: password lasts years → token expires.
  • If stolen: change the password everywhere → the server just cancels the token.
The flow

Log in once, show the token every time after

1. LOGIN (once)
   App → Server : email + password
   Server checks ✅  →  App : token "a7f3k9x2..."

2. EVERY TAP AFTER
   App → Server : "show my orders" + token
   Server : valid token → it's Aiyappa ✅
⚠️ Misconception

A token is NOT an encrypted password

  • It's a new random string the server invents.
  • An encrypted password can be decrypted back. A token has no password inside.
  • Steal the wristband and you learn nothing about the wallet.
🧭 Where & when

When to reach for it, and when not to

  • Where: every logged-in app (Swiggy, Instagram, banking).
  • When: the server must know who sent each request after login.
  • When NOT: public data anyone can read needs no identity and no token.
  • From scratch: step 1 is a login endpoint that checks the password and returns a token.
🎤 Q&A recall

Interview check

  • Q: Password vs token?
  • A: A token is issued after the password is verified. It's random, scoped to one service, short-lived and revocable. The password crosses the network once.
  • Q: What does "HTTP is stateless" mean?
  • A: No memory between requests, so each request must prove who it's from. A token does that safely.
Recap

What we locked in

  • Servers are stateless. They forget you every request.
  • Token = wristband: cheap to lose, expires, can be cancelled.
  • Next: Authentication ("who are you?") vs Authorization ("what may you do?").
