Track A · W1 · Topic 02

How a program speaks, and where it starts.

println — the serving hatch.
fun main() { } — the front door.

1️⃣ The problem

A computer working makes no sound

It adds, compares and decides entirely inside itself — silently.

Without an instruction to say something, there is no way to tell whether it did brilliant work or nothing at all.

The work is invisible.

2️⃣ The picture

The kitchen with no serving hatch

A magnificent cook, locked in a kitchen with no opening to pass food through. He cooks all day. You sit outside starving, with no evidence he exists.

println is the serving hatch — the one opening between inside and outside. Nothing else comes out.

💻 Every token

println("Hello Aiyappa")

  • println — the tool's name. print = show it (from the 1960s, when output came out on paper). ln = line → move down after.
  • ( ) — where you hand the tool the thing to work on. Always a pair.
  • " " — "stop reading this as an instruction — it's plain text." A piece of text is called a String.
The ln is independent

Two ways to make a blank line

println("")   // hand it empty text
println()     // hand it nothing at all   ← the professional one

print("Kodagu")     // print = println minus the line break
print("Madikeri")   // → KodaguMadikeri

The ln fires no matter what — even with nothing to show, it still moves to a new line.

🧭 When NOT to — senior signal

Never ship a println

  • No tag, no level → can't be filtered or switched off, and it survives into the release build. Android uses Log.d / Timber instead.
  • 🔒 Never print sensitive data. Logs are files — collected, shipped to servers, read by people. An auth token in a log is a real security incident.
  • A debugger beats prints for anything non-trivial — breakpoints show everything at once.
  • Why "Hello World" exists: not tradition — a smoke test proving editor → translator → machine → your eyes all work.
1️⃣ The second problem

400 instructions. Where does it start?

Some lines log the user in. Some save a note. Some send mail.

Which line runs first? Which lines belong to which job? To the machine it's 400 lines in a row with no grouping and no front door.

2️⃣ The picture

The office building

  • Many rooms — accounts, reception, storeroom. Each does one job.
  • A visitor arrives. Which room do they walk into?
  • There must be one main entrance. Every other room is reachable from it — but everyone comes through that door first.
  • room = function · main entrance = main
💻 Every token

The wrapper

fun main() {
    println("Hello Aiyappa")
}
  • fun — short for function: "a named job starts here."
  • main — the special name the system hunts for on startup. No main, no start.
  • { } — the walls of the room: where the job begins and ends.
  • indentation — Kotlin does not need it. Purely for human eyes.
🧭 When NOT to

Android has no main you write

Every standalone Kotlin program has exactly one main.

But an Android app doesn't. Android itself is the front door — it calls into your code when the user taps the icon.

You write the rooms. The system owns the entrance.
That's why Android code is built around lifecycle callbacks, not a linear main.

🎤 Q&A recall

Test your understanding

  • Q: Would you use println for logging in a production Android app?
  • A: No — no tag, no level, can't be filtered, survives into release. Use Log/Timber and strip debug logs. And be disciplined about what is logged: logs get collected and read, so anything sensitive is a leak path.
  • Q: Why does println() with empty parentheses still do something?
  • A: The ln is independent of the content — it emits a line separator regardless.
Recap

What we locked in

  • println = the only way a program talks to you.
  • Quotes mean "this is text, don't interpret it." Text = a String.
  • fun main() { } = the front door. { } = the walls.
  • Shipped code logs properly and never logs secrets.
