Track A · W1 · Topic 05

What kind of thing is in the jar?

Types — and the two rules that keep money and phone numbers from silently breaking your app.

1️⃣ The problem

One symbol, two behaviours

println(5 + 3)        // → 8    numbers get ADDED
println("5" + "3")    // → 53   text gets GLUED

+ does not have one meaning.

So before running a + b, the computer must first answer: "what kind of things are these?"

That question is what a type is.

2️⃣ The picture

A photo of ₹500 vs a ₹500 note

Both show "500". You can hold either one.

You cannot buy tea with the photograph.

"500" = the photo — characters 5,0,0
500 = the note — a quantity you can do arithmetic with

The quotes are the difference between a photo and the real thing.

💣 Why it's not trivia

Every form field is text

A user types 25 into "Enter your age."

The keyboard has no idea what a number is — it sends characters. Your program receives "25". The photograph.

age + 1     // expecting 26
            // → "251"

No crash. No warning. A confident wrong answer, shown to a user.

The four you need now

Int · Double · String · Boolean

val age = 25              // Int      whole numbers
val price = 99.5          // Double   has a decimal point
val name = "Aiyappa"      // String   text, in quotes
val isRegistered = true   // Boolean  exactly two values

You never wrote the type — Kotlin looked at 25 and worked out "Int". That's type inference.

⚠️ The hole in the type system

It does NOT catch everything

"3" + 1     ✅ compiles → "31"     SILENTLY WRONG
1 + "3"     ❌ compile error          a number refuses text

Kotlin lets you glue anything onto a String.

The danger runs one direction only: text-first silently swallows numbers.

⭐ Rule 1

Is it really a number?

Phone number 9480499344 — Int or String?

  • It doesn't fit. Int maxes at ~2.1 billion. This is 9.4 billion.
  • The real reason: it isn't a quantity. Is 9480499344 + 1 a meaningful phone number? Is the average of two phone numbers anything?
  • Storing it as a number destroys data: 080-… loses its leading zero · +91 loses the + · PIN 002233 becomes 2233
⭐ Rule 1 · the keeper

Digits alone don't make a number

If you'd never do arithmetic on it,
it isn't a number — even if it's
made entirely of digits.

All Strings: phone numbers · PIN codes · Aadhaar · order IDs · OTPs · account numbers.

Common interview question. Most candidates get it wrong.

⭐ Rule 2 · 💸

Never use Double for money

println(0.1 + 0.2)     // → 0.30000000000000004

Not a Kotlin bug — every language does this. Double stores numbers in binary, and 0.1 cannot be represented exactly in binary — the same way 1/3 can't be written exactly in decimal.

💸 The real consequence

Then you're debugging money

200 students × ₹499.50 in a Double won't total ₹99,900.00. It'll be ₹99,900.000000001 — and it won't reconcile against your payment gateway.

val feePerSeatPaise: Int = 49950   // ₹499.50, EXACT
                                   // divide by 100 only to display

📌 Put the unit in the name. Six months later fee = 49950 looks like a ₹49,950 charge and someone will "fix" it.

🏆 The best moment

One missing space, found without running

asked for:  ... booked 2 seats. Paid: true
predicted:  ... booked 2 seats.Paid: true
                          ↑ one space missing

Predict your output before you run it. Ten seconds, one bug, no compiler involved.

It turns "looks about right" into "I know what this does."

Recap

What we locked in

  • + means whatever the types say it means.
  • "500" is a photo. 500 is the note.
  • Every form field arrives as text — that's the "251" bug.
  • Digits alone don't make a number. Phone numbers are Strings.
  • Money is integer paise, never Double.
